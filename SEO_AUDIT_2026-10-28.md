# NARI Health implementation audit — 28 October 2026

Implemented locally; **not committed, deployed or submitted to Google**. No DNS,
production configuration, credentials or patient records were changed.

## Findings and scope

- Static HTML/CSS/JavaScript; `routes.js` registers 38 public/private routes.
  GitHub Actions deploys to GitHub Pages; live responses confirm `Server: GitHub.com`.
  Firebase provides portal data/functions, not public-site hosting in `firebase.json`.
- Initial working tree already contained edits to `index.html` and
  `.github/workflows/static.yml`. Those were preserved; this task did not edit the workflow.
- Existing work already supplied self-canonicals, social metadata, schema and a
  generated sitemap of **29 indexable URLs**. These were validated and retained.
  No useful service page was removed or redirected to the homepage.
- Six priority pages had scope for more focused metadata. Two H1s claimed “best”;
  several FAQ answers overgeneralized online physiotherapy suitability. Location
  availability needed clearer confirmation steps. FAQ interaction depended on JavaScript.
- Existing GA4 ID: `G-9V6RCQWJEM`. No GTM container or Search Console verification
  meta tag was found. DNS/account verification may exist; it cannot be inferred from source.
  GA loaded immediately. Callback events included concern, preferred time and referral
  code; demo saves were also counted. No centralized contact-click events existed.
- Existing WebSite, MedicalOrganization, WebPage, Service, FAQPage and BreadcrumbList
  markup was retained; relevant descriptions and FAQ answers now match updated copy.
  No new clinician, clinic, review, rating or address entities were invented.
- Public images already use descriptive alt text, and expert photos have dimensions
  and lazy loading. Homepage logo used the larger PNG despite an existing WebP.
  Privacy/terms logos lacked reserved dimensions. No measured field CWV baseline was available.
- Member/doctor/admin pages remain noindex and excluded from the sitemap. Firestore
  rules have role/ownership checks; robots exclusions are not authorization. No portal
  access rules were changed or deployed, and this was not a full security audit.

## Analytics behavior and manual setup before release

- `lead_submitted`: only after live Firestore save succeeds; eligible as the callback key event.
- `phone_click`, `whatsapp_click`: contact intent only, not evidence of a completed call/chat.
- `booking_start`: navigation to member sign-in, not a confirmed consultation.
- `lead_form_start`, `lead_fallback_whatsapp`: diagnostic events, not conversions.
- Events carry no custom form values, phone numbers, health concerns, referral codes or
  WhatsApp destination/query strings. No lead event fires on a page view or demo save.
- Analytics stays off until enabled in Privacy; booking works without opting in.
  Historical GA/counter totals will not be directly comparable with opt-in-only counts.
  Search Console measurement is unaffected by the site's consent setting.

**Review GA4 Admin before deployment:** disable automatic outbound-click and form
interaction Enhanced Measurement for this stream, and review history-change page
views and any custom event rules. Automatic WhatsApp link measurement could collect
prefilled message URLs, and automatic form events could count failed submissions.
This account configuration is external and cannot be verified or changed from this
repository. Enable URL/email redaction as defense in depth. Validate with an opted-in
test browser, then verify that opt-out produces no new events. Do not mark
`booking_start` as a completed appointment. Do not add another GTM/GA snippet.
See [Google's guidance on avoiding personal data](https://support.google.com/analytics/answer/6366371).

## Business facts and deferred work

- Delhi NCR FAQ says “No” to subscriptions, while the same site advertises weekly
  and monthly memberships. It also promises cancellation before the visit. Pricing
  amounts were not replaced; owner must resolve plan/cancellation wording against
  actual policy. Existing configured amounts remain ₹199, ₹799/7 days and ₹2,499/30 days.
- Privacy lists `narihealthh@gmail.com`; main pages/config use `trust@narihealth.in`.
  Confirm intended contacts instead of silently selecting a replacement. Privacy's
  broad home-visit coverage and absolute “never share” claims elsewhere need review
  against actual local availability, processors and access roles.
- Existing “5,000+ women”, testimonials, licence-verified labels, clinician experience
  and same-day confirmation claims were not independently substantiated. No new
  claims were added; owner evidence and clinician review remain necessary. Existing
  named panel/schema entries were not expanded into unverified qualifications.
- No physical addresses or local-business profiles were invented. Genuine clinic
  pages, clinician credentials/review dates and medical review need verified input.
- No hosting migration, DNS changes, new redirect infrastructure, Search Console
  submission, production authentication test, field CWV measurement or full image
  re-encoding was performed. Preserve infrastructure and assess measured bottlenecks
  before adding tooling. This patch alone cannot guarantee indexing or ranking gains.
